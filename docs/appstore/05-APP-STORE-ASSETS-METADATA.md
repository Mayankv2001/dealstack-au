# Phase 5 — App Store assets and metadata

**Goal:** everything App Store Connect needs before submission: icon, splash,
screenshots, listing copy, privacy answers.

## Step 1 — App icon

- Source: a 1024×1024 PNG, no transparency, no rounded corners (Apple rounds
  them). Derive from the site's existing brand mark (check
  `app/favicon.ico` / `app/opengraph-image.tsx` for the canonical mark and
  emerald palette) — the icon must visibly be DealStack, not a generic glyph.
- If no vector source exists, generate a simple mark: emerald background
  (`#059669`-family — sample the real token from the Tailwind theme), white
  stacked-layers glyph (the "stack" motif), no text.
- Place at `mobile/ios/App/App/Assets.xcassets/AppIcon.appiconset/` — modern
  Xcode accepts a single 1024px icon; fill the asset catalogue accordingly.
- Tooling: `npx @capacitor/assets generate --ios` from `mobile/` with the
  source at `mobile/assets/icon.png` (and `splash.png` 2732×2732) does icons
  and splash in one pass — prefer this over hand-cutting sizes.

## Step 2 — Splash screen

- 2732×2732 PNG, brand background colour, centred logo, safe within the
  central 1200px (gets cropped on every device shape).
- Generated by the same `@capacitor/assets` run.
- Verify in Simulator: no colour "jump" between splash → WebView background →
  page load.

## Step 3 — Screenshots (App Store Connect requirement)

Required sets (as of 2026 — verify current requirements in App Store Connect
before uploading, they change):
- 6.9" (iPhone Pro Max class): 1320×2868. Mandatory.
- 6.5"/6.3" often auto-derived; provide if Connect asks.

Produce ≥4, ideally 6: homepage, deals list with filters, a deal detail/stack
view, gift-cards page, saved-deals (native feature — include it, it shows
app-ness), search. Take them in the Simulator (`xcrun simctl io booted
screenshot`) on the matching device size. Plain screenshots are acceptable;
marketing frames are optional and not worth model time.

**No fabricated content:** screenshots must show real current data from the
production site. Do not mock up deals that don't exist.

## Step 4 — Listing copy (model drafts, user approves before entry)

Draft in `docs/appstore/listing-copy.md`:
- **Name:** `<APP-NAME>` (30 chars max).
- **Subtitle** (30 chars): e.g. "Stack cashback & gift cards".
- **Description** (4000 chars): what deal-stacking is, what the app does
  (combine cashback portals, discounted gift cards, points offers; OzBargain
  signals; saved deals offline). Australian spelling. **No superlative claims
  you can't back ("best", "guaranteed savings") and no competitor names.**
- **Keywords** (100 chars): `cashback,gift cards,deals,ozbargain,rewards,
  points,shopping,australia,savings,discount` (trim to fit).
- **Support URL:** `<PRODUCTION-DOMAIN>/resources` (or a contact page — must
  actually offer a way to contact; if none exists, add a simple contact section
  to an existing page, do not build a new system).
- **Privacy Policy URL:** `<PRODUCTION-DOMAIN>/privacy` — **read the live page
  first**; it must cover the app context (analytics, no accounts). If it
  mentions only "website", add a sentence covering the app. Legal-ish copy →
  show the user before deploying.

## Step 5 — Privacy nutrition labels (answer accurately, not optimistically)

Audit before answering: does the site inside the shell run Vercel Analytics
(`@vercel/analytics` is a dependency — YES it does) or any other tracking?
Expected answers, to be verified at execution time:
- Data collected: likely "Product Interaction / Usage Data — not linked to
  identity" (Vercel Analytics is anonymised; confirm current Vercel docs).
- No accounts → no contact info, no identifiers collected by DealStack itself.
- Tracking (ATT): none — the app must NOT need the App Tracking Transparency
  prompt. If any third-party tracker is found during audit, remove it from the
  shell experience rather than declaring it.
- Record the answers and their justification in
  `docs/appstore/privacy-labels.md` so the human can enter them in Connect.

## Step 6 — Age rating & availability

- Age rating questionnaire: all "None" categories → 4+. (Deals may link to
  alcohol retailers — answer the "references to alcohol" question honestly if
  liquor stores are in the store list; check `/stores` first. This may bump the
  rating to 17+ for "unrestricted web access" — a remote-URL app should answer
  the "unrestricted web access" question NO only because navigation is locked
  to the DealStack domain with external links opening in Safari; document this
  reasoning for the review notes.)
- Availability: per CONFIG.md decision (default Australia).
- Price: Free.

## Done when

- [ ] ≥4 correctly-sized screenshots saved to `docs/appstore/screenshots/`
      (git-ignored if large; otherwise commit).
- [ ] `listing-copy.md` and `privacy-labels.md` written and **explicitly
      approved by the user**.
- [ ] Privacy policy URL live and app-inclusive.
